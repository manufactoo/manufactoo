Qué es Manufactoo

What is Manufactoo

Manufactoo es un MES (Manufacturing Execution System) de código abierto y sin código, pensado para instalarse dentro de la propia empresa — sin depender de ningún servicio en la nube. Convierte tu instancia de Odoo en la fuente de verdad de los datos maestros, y añade encima todo lo que Odoo no cubre bien en planta: pantallas de captura para el operario, trazabilidad pieza a pieza y control de secuencia.

Manufactoo is an open-source, no-code Manufacturing Execution System (MES), built to run on-premises — no cloud service required. It turns your existing Odoo instance into the source of truth for master data, and adds on top everything Odoo doesn't cover well on the shop floor: operator capture screens, unit-by-unit traceability, and sequence control.

LGPL-3.0 On-premise On-premise Sin código No-code Odoo 18 / 19

Cómo está construido

How it's built

Un backend en Spring Boot con base de datos PostgreSQL propia, y un frontend en React. Manufactoo nunca duplica los datos maestros de Odoo (productos, listas de materiales, órdenes de fabricación, operarios, work centers…): cada pantalla los consulta en vivo. Lo único que vive en la base de datos propia de Manufactoo es lo que Odoo no modela — el diseño de las estaciones, las rutas, los registros de trazabilidad y las sesiones de trabajo.

La conexión con Odoo se detecta y adapta sola a la versión instalada (18 o 19), y para el hardware de planta que un navegador normal no puede tocar (puerto serie, MQTT, impresoras de red) existe el Manufactoo Player, una app de escritorio (Electron) que siempre carga la misma página en vivo del servidor — nunca una copia empaquetada.

A Spring Boot backend with its own PostgreSQL database, and a React frontend. Manufactoo never duplicates Odoo's master data (products, bills of materials, manufacturing orders, operators, work centers…): every screen queries it live. The only thing that lives in Manufactoo's own database is what Odoo doesn't model — station designs, routes, traceability records and work sessions.

The Odoo connection auto-detects and adapts to whichever version is installed (18 or 19), and for shop-floor hardware a plain browser can't reach (serial ports, MQTT, network printers) there's the Manufactoo Player, a desktop app (Electron) that always loads the same live page from the server — never a bundled copy.

El modelo de "Apps"

The "Apps" model

La funcionalidad de Manufactoo se organiza en aplicaciones instalables, cada una con su propio grupo en el menú lateral. Hoy existe una sola app, Trazabilidad y Genealogía, que cubre todo lo relacionado con estaciones, rutas, materiales, Work Centers y genealogía — descrito en detalle en las secciones 07 a 15 de este documento. El marco de aplicaciones está pensado desde el principio para que se puedan añadir más apps independientes sin tocar las que ya existen (ver Próximas apps).

Manufactoo's functionality is organized into installable apps, each with its own group in the side menu. Today there's a single app, Traceability & Genealogy, covering everything related to stations, routes, materials, Work Centers and genealogy — described in detail in sections 07 through 15 of this document. The apps framework was built from the start so more independent apps can be added without touching the ones already installed (see More apps).

Primeros pasos

Getting started

Antes de que exista ningún usuario, Manufactoo guía la primera instalación con un asistente de 5 pasos. Solo se ejecuta una vez.

Before any user exists, Manufactoo walks through the first installation with a 5-step wizard. It only runs once.

  1. Idioma. El idioma elegido aquí se usa en todo el asistente y, después, en el panel — cada usuario puede tener el suyo propio una vez dentro.
  2. Language. The chosen language drives the whole wizard and, later, the dashboard — every user can pick their own once inside.
  3. Conexión con Odoo. Host, base de datos, usuario y clave/API key, con un botón de prueba de conexión. La versión de Odoo (18 o 19) se detecta sola — no hay ningún selector manual que pueda quedar desincronizado.
  4. Odoo connection. Host, database, user and API key/password, with a connection-test button. The Odoo version (18 or 19) is auto-detected — no manual picker that could ever fall out of sync.
  5. Datos de la empresa. Nombre y datos básicos usados para identificar la instalación.
  6. Company data. Name and basic details used to identify this installation.
  7. Usuario administrador. El primer usuario, con el que se accederá al panel a partir de ahora.
  8. Admin user. The first user — the one used to log in from now on.
  9. Resumen. Revisión final antes de confirmar y crear la instalación.
  10. Summary. Final review before confirming and creating the installation.
Navegación siempre visible Always-visible navigation Una vez dentro, el menú lateral tiene dos zonas: un grupo General que no depende de ninguna app (Panel principal, Datos maestros, Aplicaciones, Configuración, Perfil), y un grupo por cada app instalada — hoy, Trazabilidad y Genealogía. Once inside, the side menu has two zones: a General group that doesn't depend on any app (Dashboard, Master Data, Apps, Settings, Profile), and one group per installed app — today, Traceability & Genealogy.

Panel principal

Dashboard

La pantalla de inicio muestra, hoy, un único gráfico: Órdenes de fabricación abiertas — todas las que están confirmadas, en curso o por cerrar (ni en borrador, ni terminadas, ni canceladas), una junto a otra en un solo gráfico de barras con eje 0–100% compartido, ordenadas de menor a mayor avance para que lo más urgente quede arriba.

El porcentaje de cada orden es cantidad producida ÷ cantidad planeada, leído en vivo de Odoo — refleja el progreso real pieza a pieza según van pasando por las estaciones (ver Producción en Odoo), no solo cuando la orden se cierra del todo. Cada fila tiene un tooltip con el detalle exacto (accesible también por teclado), y un enlace "ver como tabla" ofrece los mismos datos en una tabla accesible normal.

The home screen shows, today, a single chart: Open manufacturing orders — every order that's confirmed, in progress or ready to close (never draft, done or cancelled), all in one shared 0–100% bar chart, sorted least-complete first so what needs attention shows up on top.

Each order's percentage is quantity produced ÷ planned quantity, read live from Odoo — it reflects real, piece-by-piece progress as units pass through stations (see Production tracking), not only once an order fully closes. Each row has a keyboard-accessible tooltip with the exact figures, and a "view as table" link offers the same data as a plain accessible table.

06 · General 06 · General

Seguridad y conexión

Security & connection

Credenciales de Odoo

Odoo credentials

La clave/API key de Odoo se guarda cifrada en reposo (AES-256-GCM) y solo se descifra en memoria, en el servidor, en el instante de hacer una llamada real a Odoo — nunca se envía al navegador.

The Odoo password/API key is stored encrypted at rest (AES-256-GCM) and only decrypted in memory, on the server, at the moment of an actual Odoo call — it never reaches the browser.

Solo API, nunca la base de datos de Odoo

API only, never Odoo's database

Manufactoo nunca abre una conexión directa a la base de datos de Odoo: todo pasa por su API oficial JSON-RPC (/jsonrpc), el mismo canal que usaría cualquier integración externa. Eso respeta la lógica de negocio propia de Odoo (validaciones, permisos, campos calculados) en vez de saltársela con SQL directo, y es lo que permite funcionar igual contra un Odoo en la nube, donde ni siquiera hay acceso a la base de datos.

Manufactoo never opens a direct connection to Odoo's database: everything goes through its official JSON-RPC API (/jsonrpc), the same channel any external integration would use. That respects Odoo's own business logic (validations, permissions, computed fields) instead of bypassing it with direct SQL, and is exactly what lets it work the same way against a cloud-hosted Odoo, where direct database access isn't even available.

Por qué el asistente pide el nombre de la base de datos

Why the wizard asks for the database name

Odoo es multi-inquilino: un mismo servidor puede alojar varias bases de datos completamente independientes (empresas o entornos distintos), cada una con sus propios usuarios. Un usuario y contraseña solo son únicos dentro de una base concreta, así que el nombre de la base es un parámetro obligatorio en cada llamada a la API de Odoo — no solo al conectar, también en cada lectura o escritura posterior.

Odoo is multi-tenant: a single server can host several completely independent databases (different companies or environments), each with its own users. A username and password are only unique within one database, so the database name is a required parameter on every Odoo API call — not just at login, but on every read or write that follows.

Sesiones de usuario

User sessions

Cada sesión de persona se autentica con un token JWT. Hoy existe un único rol, ADMIN — pensado para ampliarse a más roles más adelante.

Every human session authenticates with a JWT token. Today there is a single role, ADMIN — designed to grow into more roles later.

Los Player nunca usan una contraseña de persona

Players never use a human password

Un Manufactoo Player (sección 10) se autentica como dispositivo, con un token propio (X-Player-Token) obtenido por emparejamiento — ninguna contraseña de usuario toca nunca un PC de planta.

A Manufactoo Player (section 10) authenticates as a device, with its own token (X-Player-Token) obtained through pairing — no user password ever touches a shop-floor PC.

Odoo 18 y 19, sin selector manual

Odoo 18 and 19, no manual picker

Una capa de adaptador ligera detecta la versión de Odoo en el momento de conectar y ajusta las llamadas donde hace falta — nunca hay que decírselo a mano, ni puede quedar desincronizado.

A thin adapter layer detects the Odoo version at connection time and adjusts calls where needed — it never has to be told by hand, and it can never fall out of sync.

Trazabilidad y Genealogía

Traceability & Genealogy

La primera app de Manufactoo. Captura lo que pasa en cada punto de la planta, obliga a que cada unidad siga la secuencia correcta, y opcionalmente devuelve el progreso real a Odoo — todo sin duplicar los datos de Odoo.

Manufactoo's first app. It captures what happens at every point on the shop floor, enforces that each unit follows the correct sequence, and optionally feeds real progress back into Odoo — all without duplicating Odoo's data.

Las ocho secciones siguientes (08 a 15) describen, de menor a mayor nivel, todo lo que trae esta app: primero sus piezas de entrada (dispositivos, el diseñador de estaciones), después cómo se ejecutan en planta, y por último las tres capacidades que se construyen encima — Rutas, Materiales, Work Centers y el descuento de producción real en Odoo — hasta llegar a la Genealogía, que las reúne todas.

The eight sections that follow (08 to 15) describe, from the ground up, everything this app brings: first its building blocks (devices, the station builder), then how they run on the floor, and finally the three capabilities built on top — Routes, Materials, Work Centers and real production write-back into Odoo — ending with Genealogy, which ties them all together.

Los Eventos son topics MQTT (broker embebido, sin nube) con una dirección: suscripción (un topic entrante rellena un campo solo) o publicación (una estación puede enviar un valor hacia fuera, p. ej. a un PLC o una baliza).

Events are MQTT topics (embedded broker, no cloud) with a direction: subscribe (an incoming topic fills a field automatically) or publish (a station can push a value out, e.g. to a PLC or a beacon).

Diseñador de estaciones

Station builder

El corazón de la app: un editor de arrastrar y soltar sobre una rejilla de 12 columnas y filas de alto fijo, sin escribir código. Una estación es una secuencia de una o varias pantallas, cada una con los widgets que hagan falta. La misma geometría se usa en el diseño y en producción — WYSIWYG: lo que se diseña es exactamente lo que ve el operario, escalado al ancho de su pantalla. Esta página documenta todo lo que se puede configurar, campo a campo.

The heart of the app: a drag-and-drop editor over a 12-column grid with fixed-height rows, no code required. A station is a sequence of one or more screens, each holding whatever widgets it needs. The exact same geometry is used in design and in production — WYSIWYG: what you design is exactly what the operator sees, scaled to their screen's width. This page documents everything that can be configured, field by field.

El lienzo

The canvas

Rejilla de 12 columnas fraccionales (1fr) y filas de 56px de alto fijo — igual en el editor que en producción, así el diseño escala en horizontal a cualquier pantalla sin perder proporción. Los widgets se arrastran desde una paleta lateral o se añaden con un clic; se mueven y redimensionan directamente sobre la rejilla. Al seleccionar un widget aparece una barra de estilo flotante (tamaño de texto, color) y, en los widgets de texto/etiqueta, edición del contenido en línea, sin diálogos aparte. Un widget PANEL permite agrupar visualmente otros widgets encima suyo (siempre se pinta detrás) — es puramente decorativo, no crea ninguna relación de datos entre lo que contiene.

A 12-column fractional (1fr) grid with fixed 56px-tall rows — identical in the editor and in production, so the design scales horizontally to any screen without losing proportion. Widgets are dragged from a side palette or added with a click; they're moved and resized directly on the grid. Selecting a widget shows a floating style bar (text size, color) and, on text/label widgets, inline content editing, no separate dialogs. A PANEL widget visually groups other widgets placed on top of it (always painted behind) — purely decorative, it creates no data relationship between what it contains.

Filtros contextuales de las tablas Odoo

Contextual filters on Odoo tables

Tres casillas/selectores, disponibles según el origen de datos, que estrechan qué filas de Odoo se ofrecen — todos "fallan abiertos": si falta el dato que necesitan para filtrar, muestran todo sin filtrar en vez de dejar al operario sin opciones:

  • "Limitar por producto de la ruta" (filterByStationRoute, solo ODOO_MANUFACTURING_ORDERS): si esta estación es paso de una Ruta con producto fijado (sección 11), solo enseña las MO de ese producto.
  • Work Center de la estación (automático, sin casilla, solo ODOO_WORKORDERS): si la estación tiene un Work Center de Odoo asociado, las órdenes de trabajo se limitan a ese Work Center.
  • "Estrechar a una operación" (operationId, solo ODOO_WORKORDERS en una Tabla): dentro del Work Center, reduce aún más a una operación concreta de la BOM (útil si la misma estación repite un mismo Work Center para dos operaciones distintas).

Three checkboxes/selectors, available depending on the data source, that narrow which Odoo rows are offered — all of them "fail open": if the data they need to filter by is missing, they show everything unfiltered instead of leaving the operator with no options:

  • "Limit by route's product" (filterByStationRoute, ODOO_MANUFACTURING_ORDERS only): if this station is a step of a Route with a fixed product (section 11), only shows MOs for that product.
  • Station's Work Center (automatic, no checkbox, ODOO_WORKORDERS only): if the station has an Odoo Work Center linked, work orders are limited to that Work Center.
  • "Narrow to an operation" (operationId, ODOO_WORKORDERS on a Table only): within the Work Center, narrows further to one specific BOM operation (useful if the same station reuses a Work Center for two different operations).

Two special field roles

Cualquier widget que capture datos con un origen Odoo adecuado (Desplegable, Tabla de selección única, o Texto validado) puede marcarse con una casilla como uno de estos dos roles fijos — son mutuamente excluyentes en el mismo widget:

  • "Es el identificador" — dice qué campo identifica la unidad física. Lo usan las Rutas (sección 11) para exigir la secuencia y la Genealogía (sección 15) para poder buscar una pieza. Sin él, esa estación no puede formar parte de ninguna ruta ni aparecer en genealogía por identificador.
  • "Es la orden de fabricación" — solo aparece en campos con origen ODOO_MANUFACTURING_ORDERS. Dice qué campo decide sobre qué orden de Odoo cuenta este envío. Lo usa el descuento de producción real (sección 14) — y ese descuento exige además un identificador en el mismo envío.

Any data-capturing widget with a suitable Odoo source (Dropdown, single-select Table, or validated Text) can be marked, via a checkbox, as one of these two fixed roles — mutually exclusive on the same widget:

  • "Is the identifier" — says which field identifies the physical unit. Used by Routes (section 11) to enforce sequence and by Genealogy (section 15) to search for a unit. Without it, that station can't be part of any route or show up in genealogy by identifier.
  • "Is the manufacturing order" — only shows up on fields sourced from ODOO_MANUFACTURING_ORDERS. Says which field decides which Odoo order this submission counts toward. Used by real production tracking (section 14) — which also requires an identifier in that same submission.

Dispositivo o evento asociado a un campo

Device or event wired to a field

Cualquier campo de datos puede asociarse a un dispositivo de entrada (p. ej. un lector) o a un evento MQTT de entrada (un topic de suscripción de la app Eventos) — mutuamente excluyentes. En el runtime aparece un badge indicando el origen. Con el Player, el dato real rellena el campo solo (ver sección 10); en el navegador, un lector en emulación de teclado ya funciona igual sin más configuración.

Any data field can be linked to an input device (e.g. a reader) or an incoming MQTT event (a subscribe topic from the Events app) — mutually exclusive. The runtime shows a badge naming the source. With the Player, the real data fills the field automatically (see section 10); in a browser, a keyboard-wedge reader already works the same way with no extra setup.

Código leído vs. mostrado vs. guardado

Code read vs. shown vs. saved

Un lector normalmente lee un código (p. ej. la credencial 0001 de un operario), no su nombre ni su id de Odoo. La columna de coincidencia (lookupColumn, solo aparece con un origen Odoo) dice por qué campo de Odoo buscar ese código (p. ej. barcode). Al resolver: el desplegable/tabla muestra el nombre (para que el operario confirme visualmente quién/qué es), y en trazabilidad se guarda siempre el id estable de Odoo — nunca el código en bruto ni el nombre, que pueden cambiar.

A reader normally reads a code (e.g. an operator's badge 0001), not their name or Odoo id. The match column (lookupColumn, only shows up with an Odoo source) says which Odoo field to search that code by (e.g. barcode). Once resolved: the dropdown/table shows the name (so the operator visually confirms who/what it is), and traceability always saves the stable Odoo id — never the raw code or the name, which can change.

Texto validado sin lector

Validated text without a reader

Un TEXT_INPUT sin dispositivo/evento también puede validar lo tecleado: si se le da un origen Odoo y una columna de coincidencia, cada cambio (con un pequeño retardo) se comprueba contra Odoo y avisa si el código no existe. A diferencia de un Desplegable, aquí se guarda el propio código tecleado, no un id — y el backend revalida siempre al enviar, nunca confía solo en el navegador.

A TEXT_INPUT with no device/event can also validate what's typed: given an Odoo source and a match column, every change (after a short debounce) is checked against Odoo and warns if the code doesn't exist. Unlike a Dropdown, here the typed code itself is saved, not an id — and the backend always re-validates on submit, never trusting the browser alone.

Etiquetas vinculadas

Bound labels

Una Etiqueta (LABEL) puede, en vez de texto fijo, vincularse (boundTo) a cualquier otro widget que capture datos en la misma estación, y elegir qué dato mostrar (boundField): el valor crudo introducido (_value, vale para cualquier widget), o — si el origen trae datos de Odoo — cualquier columna del registro resuelto: la fila elegida en un Desplegable o Tabla, o el registro encontrado por un Texto validado. Así una sola Etiqueta puede mostrar, por ejemplo, el departamento del operario escaneado, sin que el propio desplegable de Operario tenga que enseñarlo. En el editor se ve un valor de ejemplo (aún no hay datos reales); en producción se calcula en vivo.

A Label (LABEL) can, instead of fixed text, be bound (boundTo) to any other data-capturing widget on the same station, and choose which of its data to show (boundField): the raw entered value (_value, works for any widget), or — if the source carries Odoo data — any column of the resolved record: the row chosen in a Dropdown or Table, or the record found by a validated Text field. This lets one Label show, for instance, the department of the scanned-in operator, without the Operator dropdown itself having to display it. The editor shows a sample value (no real data yet); production computes it live.

Imágenes vinculadas

Bound images

El widget IMAGE tiene dos modos: imagen estática (se sube un fichero) o imagen vinculada (imageSource = BOUND). En modo vinculado se elige otro widget de la estación — normalmente un Desplegable o Texto validado de Productos o Operarios de Odoo — y el IMAGE muestra en vivo su campo image_128. Si el widget origen no tiene un campo de imagen (p. ej. una lista estática o un origen sin image_128), el diseñador ve un aviso y no se permite guardar la vinculación. En el editor se ve el placeholder habitual; en runtime se actualiza con la foto real del registro seleccionado.

The IMAGE widget has two modes: static image (upload a file) or bound image (imageSource = BOUND). In bound mode you pick another widget on the station — usually a Dropdown or validated Text bound to Odoo Products or Operators — and the IMAGE shows its image_128 field live. If the source widget has no image field (e.g. a static list or a source without image_128), the designer sees a warning and the binding cannot be saved. The editor shows the usual placeholder; runtime updates with the actual photo of the selected record.

Campos "sticky" y "finaliza el flujo"

"Sticky" fields and "finishes the flow"

sticky (Desplegable, Texto, Número, Tabla) evita que ese campo se limpie tras cada envío — se mantiene para la siguiente unidad (el operario de turno se elige una vez, no en cada pieza). finalizesFlow (Desplegable, Texto) hace que confirmar ese campo (elegir una opción, o pulsar Enter tras escanear) registre la unidad como OK al instante, sin necesitar un botón "Finalizar" aparte — pensado para estaciones de un solo gesto: escanear y listo.

sticky (Dropdown, Text, Number, Table) stops that field from clearing after each submission — it's kept for the next unit (the shift operator is picked once, not per piece). finalizesFlow (Dropdown, Text) makes confirming that field (choosing an option, or pressing Enter after a scan) submit the unit as OK instantly, with no separate "Finish" button needed — built for one-gesture stations: scan and done.

Rutas

Routes

Una ruta define la secuencia de estaciones obligatoria para un producto — opcionalmente ligada a un producto concreto de Odoo, o genérica ("cualquier producto"). Cada ruta declara qué campo identifica la unidad a lo largo del recorrido (identifierBindingKey) — normalmente el mismo campo marcado como "Es el identificador" en cada estación.

Cumplimiento: al enviar un registro, Manufactoo comprueba todas las rutas habilitadas que incluyen esa estación. Si el envío no trae el identificador de una ruta, esa ruta simplemente no aplica a esa unidad. Si lo trae, exige que todos los pasos anteriores ya tengan un registro con ese mismo identificador — si falta uno, rechaza el envío con un mensaje claro. Una unidad nunca puede saltarse un paso. Deshabilitar la ruta levanta la restricción al instante.

A route defines the mandatory sequence of stations for a product — optionally tied to a specific Odoo product, or left generic ("any product"). Every route declares which field identifies the unit along the way (identifierBindingKey) — usually the same field marked "Is the identifier" on each station.

Enforcement: on every submission, Manufactoo checks every enabled route that includes that station. If the submission doesn't carry that route's identifier, that route simply doesn't apply to that unit. If it does, it requires that every earlier step already has a record with that same identifier — if one is missing, the submission is rejected with a clear message. A unit can never skip a step. Disabling the route lifts the restriction instantly.

Materiales

Materials

Registra qué lotes/series están cargados ahora mismo en una estación — por ejemplo, los carretes de componentes de una máquina de pick&place. Es un dato de presencia en la estación, no una copia del stock: el lote sigue viviendo en Odoo. Cada unidad que pasa mientras un lote está activo lo hereda automáticamente en su registro de trazabilidad, sin que el operario tenga que volver a elegirlo unidad a unidad.

Tracks which lots/serials are loaded right now at a station — e.g. the component reels on a pick-and-place machine. It's presence-at-the-station data, not a copy of stock: the lot still lives in Odoo. Every unit that passes through while a lot is active automatically inherits it in its trace record, with no need for the operator to re-select it per unit.

Work Centers

Work Centers

El widget WORKORDER_ACTIONS añade controles de Start / Pausar / Bloquear / Finalizar más una cantidad en curso, sobre la orden de trabajo elegida en una tabla vinculada. Escribe de verdad en el propio modelo de Órdenes de trabajo de Odoo — pausar, bloquear (con motivo) y finalizar se reflejan de inmediato en Odoo, incluyendo atribuir el tiempo trabajado al operario real que fichó, no a la cuenta de integración.

The WORKORDER_ACTIONS widget adds Start / Pause / Block / Finish controls plus a running quantity, over the work order chosen in a linked table. It writes for real into Odoo's own Work Order model — pausing, blocking (with a reason) and finishing all reflect immediately in Odoo, including attributing worked time to the actual scanned-in operator, not the integration account.

Escritura estricta Strict write policy Si Odoo rechaza la escritura, no se guarda nada en Manufactoo tampoco — no existe un estado "pendiente de sincronizar" ni una cola de reintentos. Los dos sistemas nunca pueden divergir en silencio. If Odoo rejects the write, nothing is saved on the Manufactoo side either — there is no "pending sync" state or retry queue. The two systems can never silently drift apart.

La pantalla cruzada Work Centers muestra, de toda la planta a la vez, cada sesión activa: estación, orden de trabajo, operario, estado, tiempo transcurrido y cantidad frente al objetivo.

The cross-plant Work Centers screen shows every active session at once: station, work order, operator, state, elapsed time, and quantity against target.

Producción real en Odoo

Real production tracking

Opcional, y se activa marcando un campo como "Es la orden de fabricación" en una estación. A partir de ahí, cada unidad aceptada que llegue al final de su ruta (o a una estación sin ninguna ruta) cuenta +1 hacia la cantidad producida de esa orden en Odoo — en vivo, pieza a pieza, no solo cuando la orden se cierra entera.

Optional, turned on by marking a field as "Is the manufacturing order" on a station. From then on, every accepted unit that reaches the end of its route (or a station with no route at all) counts +1 toward that order's produced quantity in Odoo — live, piece by piece, not only once the whole order closes.

Sin backorders No backorders El descuento avanza directamente la cantidad en curso de la orden — el mismo efecto que editar a mano la cantidad "consumida" en el propio formulario de Odoo — y solo cierra la orden cuando la última unidad iguala exactamente lo planeado. Nunca deja una orden partida en dos. The write-back advances the order's own in-progress quantity directly — the same effect as editing the "consumed" quantity by hand in Odoo's own form — and only closes the order once the very last unit exactly matches what was planned. It never leaves a split order behind.

El consumo de materia prima se calcula siempre a partir de la proporción estable de la propia Lista de materiales (cantidad del componente ÷ cantidad que produce la BOM), nunca de un campo del movimiento de stock que cambia según el progreso — evita que la ración se desvíe unidad a unidad.

Raw-material consumption is always computed from the Bill of Materials' own stable ratio (component quantity ÷ BOM yield), never from a stock-movement field that changes as production progresses — this prevents the ratio from drifting unit by unit.

Qué unidad exactamente

Which unit exactly

Necesita, en el mismo envío, un campo marcado "Es el identificador" — así Odoo sabe a qué lote/serie concreto atribuir la unidad producida (lot_producing_ids).

It needs, in that same submission, a field marked "Is the identifier" — so Odoo knows exactly which lot/serial to record as the produced unit (lot_producing_ids).

Consciente del seguimiento real del producto

Aware of the product's real tracking

Manufactoo consulta en vivo si el producto de esa orden lleva seguimiento por lote/serie en Odoo. Si no lo lleva, no exige ni escribe ningún identificador. Si lo lleva, el identificador es obligatorio y tiene que pertenecer a ese mismo producto — un lote de otro producto se rechaza, nunca se acepta por error.

Manufactoo checks live whether that order's product is actually lot/serial tracked in Odoo. If it isn't, no identifier is required or written. If it is, the identifier is mandatory and must belong to that same product — a lot from a different product is rejected outright, never accepted by mistake.

Solo el último paso de una ruta

Only the last step of a route

Si la estación es parte de una ruta, solo la última estación de esa ruta descuenta producción — los pasos intermedios nunca cuentan, aunque también tengan un campo de orden de fabricación configurado.

If the station is part of a route, only the last station of that route deducts production — intermediate steps never count, even if they also happen to have a manufacturing-order field configured.

Genealogía

Genealogy

Busca cualquier unidad por su identificador y ve su recorrido completo: cada estación por la que pasó, en orden, con el operario, la fecha/hora y todo lo que se capturó en ese paso. También lista la actividad más reciente de toda la planta, para un vistazo rápido sin buscar una unidad concreta.

Se construye enteramente a partir de los mismos registros inmutables que ya genera cada envío de estación — no hace falta configurar nada más allá de marcar un campo como "Es el identificador" en algún punto de la secuencia.

Search any unit by its identifier and see its full path: every station it passed through, in order, with the operator, timestamp, and everything captured at that step. It also lists the plant's most recent activity, for a quick glance without hunting for a specific unit.

It's built entirely from the same immutable records every station submission already produces — nothing else to configure beyond marking a field as "Is the identifier" somewhere in the sequence.
